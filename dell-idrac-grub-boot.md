# Known Issue: Dell PowerEdge — iDRAC Virtual Media Boot Drops to grub> Prompt

**Affects:** Dell PowerEdge servers booting a Palette Edge installer ISO via iDRAC virtual media  
**Symptom:** Installer drops to a bare `grub>` prompt instead of launching  
**Status:** Fix available (grub.cfg change in CanvOS build); distinct from PE-8277

---

## What's happening

When the Palette Edge installer ISO is mounted and booted via iDRAC virtual media, Dell firmware enumerates the virtual CD-ROM drive as `cd0` rather than `hd0`. The `grub.cfg` embedded in the ISO contains a search directive that looks for the installer by file path on a hard disk device — it never finds `cd0`, so GRUB loads successfully but can't locate its config and drops to the interactive prompt.

This is distinct from **PE-8277** (a separate issue where `grubx64.efi` itself fails to load on some Dell hardware due to EFI binary incompatibility). In the `grub>` prompt scenario, GRUB has already loaded successfully — the EFI binary is fine.

---

## Confirming the diagnosis

At the `grub>` prompt, run:

```
ls
```

If you see `(cd0)` in the output alongside `(hd0)` entries, this is the iDRAC enumeration issue. The installer media is on `cd0`, not `hd0`.

---

## Immediate workaround (manual, no rebuild required)

At the `grub>` prompt:

```
set root=(cd0)
configfile /boot/grub2/grub.cfg
```

This manually points GRUB at the correct device and loads the config. The installer will launch normally. This workaround must be repeated each time the host boots from the ISO.

---

## Permanent fix (requires CanvOS rebuild)

The root cause is the search directive at the top of `overlay/files-iso/boot/grub2/grub.cfg` in the CanvOS repository. The existing line searches for a file (`/boot/kernel.xz`) which only scans hard disk devices on Dell hardware.

**Replace the existing search line** with a label-based search that works across device types:

```grub
# Fix for Dell iDRAC virtual media: firmware enumerates installer as cd0 not hd0.
# Label-based search finds the correct device regardless of type.
search --no-floppy --label --set=root COS_LIVE
if [ -z "$root" ]; then
  search --no-floppy --file --set=root /boot/grub2/grub.cfg
fi
```

This change:
- Uses the ISO's volume label (`COS_LIVE`) which is already referenced in the kernel command line, so it's consistent with the rest of the boot process
- Falls back to a file-based search if the label isn't visible
- Works for USB boot, iDRAC virtual media, and physical CD-ROM without needing to hardcode a device name

After making this change, rebuild the ISO with:

```bash
export EARTHLY_DISABLE_REMOTE_REGISTRY_PROXY=1
sudo -E earthly +build-all-images
```

Or to rebuild just the ISO without rebuilding provider images:

```bash
sudo earthly --no-cache +iso
```

---

## Affected hardware

Confirmed on Dell PowerEdge R340 and R450. The issue appears to be firmware-level and may affect any Dell PowerEdge that presents iDRAC virtual media as a CD-ROM device rather than a USB mass storage device.

The same ISOs boot correctly on non-Dell hardware and on Dell hardware booted from a physical USB drive.

---

## Relationship to PE-8277

PE-8277 tracks a separate issue where `grubx64.efi` generated by CanvOS fails EFI binary validation on some Dell firmware, preventing GRUB from loading at all. If the system shows an EFI load error *before* any GRUB output, that is PE-8277. If GRUB loads and shows a `grub>` prompt, that is the device enumeration issue documented here.

Both can be present on the same hardware; the grub.cfg fix above addresses only the enumeration issue.
